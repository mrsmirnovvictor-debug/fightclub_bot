# 🥊 Fight Club Bot

Телеграм-бот с игрой «Бойцовский клуб» по мотивам combats.ru: персонаж
создаётся в личке бота, а кулачные дуэли идут в отдельной ветке группы, где бот
работает судьёй и комментирует каждый удар.

## Что уже умеет MVP

* **Создание персонажа в личке**: класс → прозвище → аватар (эмодзи или своё
  фото) → распределение стартовых характеристик.
* **Четыре класса**: воин, ловкач, ассасин, танк — с разными боевыми ролями.
* **Четыре характеристики**: сила, ловкость, интуиция, выносливость.
* **Дуэли в ветке группы**: вызов всем желающим или конкретному бойцу, приём
  вызова кнопкой, пошаговый бой с блоками и зонами удара.
* **Судья-рассказчик**: каждый раунд бот описывает оба удара живым текстом и
  показывает полоски здоровья.
* **Прогресс**: опыт, уровни, свободные очки характеристик, таблица чемпионов,
  история боёв.

## Быстрый старт

```bash
git clone <repo> && cd fightclub_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # и вписать BOT_TOKEN от @BotFather
python -m bot.main
```

Переменные окружения (`.env`):

| Переменная          | По умолчанию    | Смысл                                      |
|---------------------|-----------------|--------------------------------------------|
| `BOT_TOKEN`         | —               | токен от [@BotFather](https://t.me/BotFather) |
| `DB_PATH`           | `fightclub.db`  | файл базы SQLite                            |
| `TURN_TIMEOUT`      | `60`            | секунд на выбор удара и блоков              |
| `CHALLENGE_TIMEOUT` | `180`           | сколько живёт неотвеченный вызов            |

### Настройка группы

1. Создайте группу (лучше супергруппу с включёнными темами/форумом).
2. Добавьте бота в группу.
3. Создайте отдельную тему для боёв и отправьте там `/arena` — бот запомнит эту
   ветку и будет судить только в ней. Команду может выполнить только админ.
4. Каждый участник пишет боту в личку `/start` и собирает бойца.
5. В ветке клуба — `/duel`, дальше по кнопкам.

> Если в BotFather у бота включён privacy mode, команды (`/duel`, `/arena`)
> он всё равно видит. Отключать privacy mode не требуется.

## Как устроен бой

Пять зон: 🧠 голова, 🫁 грудь, 🍺 живот, 🥋 пояс, 🦵 ноги.

Каждый раунд боец выбирает **одну зону удара** и закрывает блоком столько зон,
сколько положено его классу (обычно две, у танка — три). Обе стороны жмут кнопки
под одним и тем же сообщением в ветке: чужой выбор не виден, бот отвечает
всплывающей подсказкой только тому, кто нажал. Кто не успел за `TURN_TIMEOUT` —
за того выбирает судья.

Порядок разбора удара:

1. Зона закрыта блоком → урона нет.
2. Иначе бросается уворот (ловкость защитника минус интуиция атакующего). При
   удачном уворте возможен контрудар вполсилы.
3. Иначе — урон, с шансом на крит (интуиция + бонус класса).

Оба удара считаются от состояния на начало раунда, поэтому возможен двойной
нокаут — в этом случае побеждает тот, чей удар прошёл первым (ловкость +
интуиция). С 6-го раунда бойцы устают и урон растёт, а после 20-го раунда судья
присуждает победу по остатку здоровья.

### Классы

| Класс        | Роль                                   | Особенность                         |
|--------------|----------------------------------------|-------------------------------------|
| ⚔️ Воин      | ровный боец                            | больше всех здоровья и урон выше среднего |
| 🤸 Ловкач    | уворот и наказание за промах           | 26% к увороту, почти всегда контрудар |
| 🗡️ Ассасин   | один точный удар решает                | +20% к криту, крит ×2.0             |
| 🛡️ Танк      | стена                                  | закрывает блоком три зоны из пяти   |

Баланс проверяется симулятором (винрейты держатся в коридоре 44–56%):

```bash
python scripts/simulate.py --balance      # винрейты всех пар
python scripts/simulate.py                # один бой с комментариями судьи
```

### Характеристики

* **💪 Сила** — урон.
* **🤸 Ловкость** — уворот и инициатива.
* **🔮 Интуиция** — крит, контрудар и точность (сбивает уворот соперника).
* **🫀 Выносливость** — здоровье.

На старте боец получает 6 очков (не больше 4 в один стат), за каждый уровень — ещё 2.

## Архитектура

```
bot/
├── main.py            точка входа: бот, диспетчер, база, сервис дуэлей
├── config.py          настройки из .env
├── database.py        SQLite (aiosqlite): бойцы, арены, история боёв
├── models.py          Player, Arena, опыт и уровни
├── keyboards.py       инлайн-клавиатуры и callback-фабрики
├── duel_service.py    состояние дуэлей: вызовы, раунды, таймеры, награды
├── game/
│   ├── classes.py     классы, зоны, характеристики
│   ├── stats.py       производные боевые показатели
│   ├── combat.py      чистый боевой движок (без телеграма)
│   └── narrator.py    тексты судьи
└── handlers/
    ├── creation.py    FSM создания персонажа и прокачки
    ├── profile.py     профиль, справка, топ
    └── group.py       ринг, вызовы, нажатия во время боя
```

Боевой движок (`bot/game/`) не знает про Telegram — его можно гонять
симулятором и тестами. `DuelService` держит активные бои в памяти и обращается к
Bot API только через отправку/редактирование сообщений.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

45 тестов и ни одного обращения к Telegram:

* боевой движок, баланс и завершаемость боя для всех пар классов;
* опыт, уровни и хранилище;
* сквозная дуэль через `DuelService` с поддельным ботом — от вызова до записи
  результата в базу;
* регистрация персонажа и групповой бой прогоняются через настоящий
  `Dispatcher` aiogram с подменённой сессией Bot API, так что фильтры,
  состояния FSM и callback-данные проверяются по-настоящему.

## Известные ограничения MVP

* Активные бои живут в памяти процесса: при рестарте бота текущий бой
  прерывается (бот честно пишет об этом в ветку), статистика и персонажи в базе
  не страдают.
* Один бой на ветку одновременно.
* Экипировки, инвентаря, магазина и групповых боёв пока нет.
