Все изображения лежат в Cloudflare R2, bucket `vegas-fight-club`, префикс `locations/`.

- Public base: `https://pub-44581ebfe3a240b9b46b8d169429b1c0.r2.dev`
- Формат: JPEG, RGB
- Исходный размер каждой карты: `941 × 1672` px
- Ориентация: portrait, соотношение сторон около 9:16
- Камера: объёмный верхний/isometric ракурс

## Правило отображения и нажатий

Показывать всю карту через `object-fit: contain`, без обрезки. Hotspot — `entrance`: четырёхугольник по видимой двери, воротам или открытому входу здания, заданный массивом нормализованных точек `[x,y]` (диапазон 0–1, начало координат в левом верхнем углу самого изображения). Точки перечислены по часовой стрелке; последнюю точку с первой замыкает клиент. Если вокруг изображения появились letterbox-поля, сначала вычесть их смещение и только затем нормализовать координаты касания.

Пиксельная точка входа вычисляется так: `px=x*941`, `py=y*1672`. Попадание проверяется обычным point-in-polygon. Для визуальной подсветки рисовать этот же четырёхугольник поверх двери.

Четырёхугольник описывает только видимый вход. Поскольку дверь мала для пальца, фактическую невидимую область касания следует расширить минимум на 2.5% ширины и 1.5% высоты изображения с каждой стороны, но видимая подсветка обязана оставаться точно на `entrance`. Общая зона выхода со всех карт в выбор района: `{x: 0.35, y: 0.84, w: 0.30, h: 0.14}` (нижний центральный проход).

## Рекомендованная модель данных

Каждая карта: `id`, `image`, `hotspots`. Каждый hotspot: `id`, `entrance`, `action`. `entrance` всегда содержит ровно четыре нормализованные точки. Для перехода между районами нижняя зона вызывает `open_location_picker`; входы вызывают соответствующий экран или рейд. Не привязывать зоны к размеру DOM-элемента напрямую и не использовать координаты viewport — только координаты фактически отрисованного изображения.
